🏫 School Fundraising — Buggy Donations Filter

Full Stack NestJS + React AI Agent Required ⏱ 30 minutes

Maple Ridge Elementary's donation dashboard has broken filters. The candidate must diagnose and fix bugs in both the React frontend and NestJS backend — using an AI coding agent. There are more bugs here than most candidates will finish in 30 minutes; triage and communication under time pressure are part of what's being evaluated.

Background

Maple Ridge Elementary is running its annual Giving Week fundraiser. Families across all grade levels donate online, and the school admin uses a dashboard to track incoming donations. Admins can filter the donation list by grade level, date range, and payment status.

Something is broken: no matter what filters the admin selects, the results come back wrong. Sometimes all records are returned regardless of the filter. Sometimes a date range that should include a donation excludes it. Your job is to find and fix as many bugs as you can in the time you have.

Your task

  1. Run the app. Set up the starter project and reproduce the broken behavior. Spend no more than 5 minutes here.
  2. Use an AI coding agent (Claude, Cursor, Copilot, or similar) to help diagnose and fix the bugs. You must use an agent — narrate your prompting approach as you go so the interviewer can follow along.
  3. Fix what you can, in both layers. There are bugs in the frontend and the backend. You are not expected to find and fix everything in 30 minutes — prioritize, and be ready to explain your triage.
  4. Add a comment above each fix explaining what was wrong and what you changed.

Ground rule: You must use an AI coding agent. Be ready to explain: what prompt you gave it, whether its first answer was correct, and how you iterated if it wasn't.

What we're evaluating

  • ✓
    Whatever filters you did fix behave correctly, including in combination with each other
  • ✓
    You tested edge cases, not just the obvious happy path (e.g. a single-sided date range, a range that starts or ends exactly on a donation's date)
  • ✓
    You made progress in both frontend and backend — most candidates will find bugs in both layers
  • ✓
    You can clearly state what's still broken and why you prioritized the way you did
  • ✓
    Each fix has a brief comment explaining what was wrong

Hints

Start by looking at what query parameters the frontend sends to the API. Then look at how the backend reads and applies those parameters. The bugs are intentional and localized — no refactoring needed. Not every bug shows up just by clicking around the UI — if you have time left after the obvious ones, try exercising the API directly (curl, Postman, or the browser's Network tab) with parameters beyond what the filter bar exposes.
